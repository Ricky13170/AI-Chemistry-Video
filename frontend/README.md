# Chemistry Studio frontend

React + TypeScript + Vite implementation of the approved teal Dashboard. English-only UI. No backend or external provider keys are required in mock mode.

## Run locally

Requires Node.js **22.12+**. Dependencies are pinned in `package.json` and `package-lock.json`.

```powershell
Copy-Item .env.example .env.local
npm ci
npm run dev
```

On macOS/Linux, use `cp .env.example .env.local` instead. Open <http://localhost:5173>. The development port is fixed; stop another process on that port or change `vite.config.ts`.

## Mock API

The default `VITE_API_MODE=mock` starts Mock Service Worker **before rendering the app**. The UI calls the same `fetch` API as real mode; MSW intercepts matching requests.

This is a **browser-level mock**, not a standalone HTTP server. `curl`, Postman, or opening an API URL in another process does not use these mocks. `npm test` reuses the handlers through MSW's Node integration.

- Any nonempty compound follows a successful demo workflow in about seven seconds.
- Enter exactly `fail-demo` to simulate a provider failure during script generation.
- Cancelling an active job prevents later progression.
- Retry creates a **new job id** with the **original settings**. Retrying `fail-demo` intentionally fails again; edit the compound and Generate to try success.
- Demo results return `is_demo: true`, a script outline, empty sources, and empty artifacts. No video, audio, or slide file is generated.
- Mock jobs are saved in localStorage under `chemistry-studio-mock-jobs-v1`. Corrupt entries are ignored. Blocked storage falls back to memory.
- The selected job id is saved separately for mock/real modes. Reloading restores that job and resumes polling while active.
- The in-progress job lives above the routes, so switching screens does not discard it. Opening a different job or resetting settings is blocked while the selected job is active.
- The illustrated player is a design demo, not an HTML video artifact. The voice sample uses an available English system voice; it does not select the eventual provider's male/female voice.

## Connect FastAPI later

Update `.env.local`:

```dotenv
VITE_API_MODE=real
VITE_API_BASE_URL=/api
API_PROXY_TARGET=http://localhost:8000
```

Restart Vite after changing environment variables. `/api` requests are proxied to FastAPI during development. The current proposed endpoint prefix is `/api`; the proxy does **not** rewrite it. If your backend uses a different prefix, align `VITE_API_BASE_URL` and the proxy configuration.

The existing backend skeleton may only expose `/health`. Setting real mode alone does not implement job endpoints. Build and reconcile the contract in `../plans/frontend-api-contract.md` against your actual Pydantic schemas first. Update `features/jobs/types.ts` and `features/jobs/api/jobs-api.ts` if the backend contract differs. Response schemas are validated at runtime so mismatches surface as errors instead of silently rendering broken data.

Successful real jobs can provide artifact URLs. Video artifacts render with native video controls; other artifacts appear as download links. Only HTTP(S) artifact/source links are rendered. Your backend must supply valid reachable media URLs; cross-origin downloads may open in a new tab instead of forcing a download.

No authentication/session handling is wired yet. Do not put LLM, TTS, storage or database secrets into `VITE_*` variables: Vite exposes those values in browser code.

## Screens and state

| Route      | State                                                                                    |
| ---------- | ---------------------------------------------------------------------------------------- |
| `/`        | Dashboard implemented; job API can be mock or real                                       |
| `/history` | History implemented with loading, empty, error and pagination states                     |
| `/user`    | Account scaffold; guest information only                                                 |
| `/login`   | Login layout scaffold; submitting only shows an explanation, sends/stores no credentials |

`Reset settings` restores the default form and clears the selected preview. It does not delete history. It is disabled while a job is pending/running. After editing settings on a completed job, Generate starts a new job; the preview keeps showing the selected result until the new job is submitted.

## Quality checks

```sh
npm run typecheck
npm test
npm run build
```

Tests cover lifecycle transitions, cancellation persistence, storage failures, retry identity, request/response validation, HTTP errors, duplicate submission, form validation, and navigation from History. These run in jsdom with MSW; they do not replace visual browser QA.

`npm run build` creates `dist/`. `npm run preview` serves that build locally. The default build remains a demo while `VITE_API_MODE=mock`; set real mode explicitly before making a real production build.

For deployment, configure your web server to serve `index.html` for application routes such as `/history` and `/login`, and separately route `/api` to FastAPI. Vite's development proxy is not part of production output. No deployment or backend changes are included in this package.
